## 5.1 aligned 字段的准确语义（GPT 复审要求澄清）

**`aligned` 不是「Pager 当前页与目标页相等」的测量值。** 它是 `TabScrollGuard.end(index)`
的 Boolean 返回值，含义为「**本次协程是否取得守卫（guard）的对齐所有权**」——
即「这次程序化滚动有没有被更新的点击取代」：

- `aligned=true` ＝ 本协程仍持有守卫所有权 → 由本协程调用 `alignRouteToPager(pagerState.currentPage)`；
- `aligned=false` ＝ 已被更新的点击取代 → 守卫标记留给那次点击，本协程不动路由。

**因此 `aligned=true` 不蕴含「当前页 == 目标页」**，只蕴含「没有更新的点击抢走所有权」。
`Route/align=N` 里的 N 才是当次对齐时 Pager 的实际停留页（= `pagerState.currentPage`）。
本轮六轮里 `Route/align` 出现值与当时的 `Route/currentPage` 一致（s1=1、s2=2、s3=0、s4=0、
s5=1、s6=2），但那是**当次恰好落定在目标页**，不是 `aligned` 字段本身的含义。

## 5.2 P2 登记：同目标连续点击的守卫所有权冲突（GPT R9 复审发现）

- **位置**：`app/src/main/java/com/screentrace/app/ui/TabScrollGuard.kt`、
  `app/src/main/java/com/screentrace/app/ui/AppNav.kt`、
  `app/src/test/java/com/screentrace/app/ui/TabScrollGuardTest.kt`。
- **复现**：R9 v3 的 s5_same（同目标连续两次点击统计页，target 均为 1）。第 1 次协程被第 2 次点击
  取消后，`tabGuard.end(1)` 因**目标仍为 1** 而错误返回 true，并清除了第 2 次点击建立的守卫状态；
  第 2 次协程结束时返回 false。日志实证：seq1 `scrollCancel→scrollFinally(aligned=true)`+
  `Route/align=1`，seq2 `scrollEnd→scrollFinally(aligned=false)` 且**无 Route/align**。
- **根因**：守卫只用 target index 区分协程，没有用点击序号区分所有权；`.end(index)` 的
  `target != index` 判据在「同目标」时失效。
- **本轮处置**：**未改任何导航业务代码**（本任务不授权）。修复设计、状态转移说明、测试设计与
  最小 diff 计划见 `docs/CR-30-A5-R10-TabScrollGuard-所有权设计.md`，待 GPT 评审后再实施。
