# A-5 刷新率字段语义分析（R6 任务一，交付 6）

> 依据：Redmi 2407FRK8EC 真机**四份完整 dumpsys display 原始输出**（idle/active × 60/120Hz
> 锁定）+ SurfaceFlinger dumpsys。原始文件：
> `evidence/a5_dumpsys_redmi_60hz.txt` / `a5_dumpsys_redmi_120hz.txt`（idle），
> `scripts/fixtures/dumpsys_redmi_{idle,active}_{60,120}hz.txt`（含 active 两份，测试 fixture）。

## 1. 字段语义结论

| 字段 | 区段/归属 | 语义 | 可否作活动面板刷新率 |
|---|---|---|---|
| `RefreshRate=`（独立行） | **PersistentDataStore → DisplayStates → 0: local:…** | **用户持久化显示状态偏好** | **否（R6 更正：此前误读，作废）** |
| `DisplayDeviceInfo{… modeId X … supportedModes[id→fps]}` | 目标显示设备块 | 当前活动/已提交**显示模式**（经本设备 mode 映射得 fps） | **是（设备绑定，主判据）** |
| `mActiveModeId` | DisplayManager 服务态 | 当前活动显示模式 id（交叉核对） | 是（与 modeId 互验） |
| `mActiveSfDisplayMode{…}` | SurfaceFlinger | SF 侧模式 | 否（SF/合成侧） |
| `mActiveRenderFrameRate` / `renderFrameRate` | 渲染侧 | 应用渲染帧率 | 否（渲染≠面板） |
| `supportedRefreshRates` / 模式列表 / `DisplayMode{peakRefreshRate=…}` | 支持能力 | 设备支持的档位 | 否（不是活动模式） |

## 2. 四快照对比证据（关键）

对 min/peak_refresh_rate 分别锁 60 与 120、并分别在 idle 与**连续渲染中**采集：

| 字段 | idle_60 | idle_120 | active_60 | active_120 |
|---|---|---|---|---|
| PDS DisplayStates.RefreshRate | 60.0 | 60.0 | 60.0 | 60.0 |
| DisplayDeviceInfo.modeId / renderFrameRate | 3 / 120.00001 | 同 | 同 | 同 |
| mActiveModeId | 3 | 3 | 3 | 3 |
| mActiveSfDisplayMode | id=2 (120.00001) | 同 | 同 | 同 |
| mActiveRenderFrameRate | 120.00001 | 同 | 同 | 同 |

整文件 diff：除时间戳/传感器/进程列表噪声外**零模式字段变化**；SurfaceFlinger
`mDisplayModePtr={id=2, … vsyncRate=120.00 Hz}` 在两种锁定下**恒为 120Hz**。

**结论**：该 ROM 上 `settings put system min/peak_refresh_rate` **未改变任何可观察的
活动显示模式字段**；PDS.RefreshRate 甚至停留在 60（且其语义本就是持久化偏好）。
即：**无法通过 dumpsys 字段的变化证明识别结果随实际活动模式变化**（任务一.5 未能取得
对照证明——因为实际模式根本未变）。

## 3. 识别方案与保留声明

- **主判据**：目标内置屏（唯一）设备块 `modeId` × 本设备 `supportedModes` 映射，
  `mActiveModeId` 交叉核对（不一致→无法确认）。该字段组为 AOSP 定义的「当前活动
  显示模式」，语义上即面板模式；**但其变化性证明在本 ROM 上无法取得**（上表）。
- **PDS/模式列表/SF/渲染率**：只记上下文，永不冒充。
- **仍有字段无法可靠识别/证实**（交付 10 明确声明）：
  1. **实际物理面板刷新率的变化性无法证实**——60/120 锁定在本 ROM 未产生可观察差异，
     无法排除「面板恒 120」或「面板切换但无字段反映」两种情形；
  2. 因此 **60Hz 样本在门禁下必然判 INVALID**（活动模式判读 120 ≠ 请求 60），
     120Hz 样本判读一致方可采样——矩阵 60Hz 列在取得有效锁定手段前**阻塞**，
     不冒充、不放行。
- **历史影响（如实提示，不擅自改历史报告原文）**：A-3-R3.1 §9.2 曾以「解析 RefreshRate=60.0」
  作为 60Hz 锁定生效的现场验证——该证据即 PDS 偏好字段，**证据无效**；A-3/A-4 报告中
  「60Hz 锁定经现场验证」类表述应按本分析更正（是否回填原文待 GPT 裁决）。
