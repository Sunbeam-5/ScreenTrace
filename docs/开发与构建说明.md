## 环境

| 项 | 要求 |
|---|---|
| JDK | **17**（`JAVA_HOME` 指向 17 最稳）。Gradle 8.7 也能跑在 21 上，见下方说明 |
| Android SDK | Platform **34**（`compileSdk = 34` / `targetSdk = 34`），Build-Tools 34.x |
| Gradle | 8.7（wrapper 已随仓库提供，不必自己生成） |
| 设备 | Android 8.0+；要完整事件流（解锁 / 通知）需安装并授权 Shizuku |

## 常用命令

```bash
./gradlew :app:assembleDebug          # 构建 debug APK
./gradlew :app:testDebugUnitTest      # 全部 JVM 单测（174 个，无需真机）
./gradlew :app:testDebugUnitTest --tests "com.screentrace.app.data.SessionUnionTest"   # 单跑某类
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

命令行构建用的是 `JAVA_HOME`，Android Studio 用的是 `Settings → Build Tools → Gradle → Gradle JDK`，
两者可以不同。`gradlew.bat -v` 可看 Terminal 实际使用的 JVM。

## 版本组合

Gradle 8.7 / AGP 8.5.2 / Kotlin 1.9.24 / Compose Compiler 1.5.14 / Compose BOM 2024.06.00 /
core-ktx 1.13.1 / Room 2.6.1 / WorkManager 2.9.0 / DataStore 1.1.1 / Shizuku 13.1.5。

## 常见故障

| 现象 | 处理 |
|---|---|
| `SDK platform 34 not found` | SDK Manager 勾装 Android 14 (API 34)，或把 `compileSdk/targetSdk` 改成已装版本（需 ≥34） |
| Gradle 下载卡住 | `settings.gradle.kts` 已配阿里云 Maven 镜像；wrapper 的 `distributionUrl` 可换成 `https://mirrors.cloud.tencent.com/gradle/`，保留文件名 `gradle-8.7-bin.zip` |
| Gradle JDK 是 21，担心与 `jvmTarget = "17"` 冲突 | 不冲突：21 是跑 Gradle 的 JVM，17 是产物字节码目标。若报 `Unsupported class file major version 65` 或 R8/D8 异常，再把 Gradle JDK 切到 17。不要在 `gradle.properties` 里硬编码 `org.gradle.java.home` |
| `Duplicate class` / Kotlin 版本冲突 | 确认 `kotlinCompilerExtensionVersion` 未被改动 |
| Sync 成功但 Run 报 `ClassNotFound` | `Build → Clean Project` 后重新 Sync；确认打开的是工程根目录而不是 `app/` |
| 装到设备后打开是旧版本 | 设备可能停在手机分身（user 999），`AdbInstallActivity` 属 user 0 会被压成 PAUSED；退出分身再装 |
| `dumpsys usagestats` 没有事件流 | 未授权 Shizuku 时会降级到 `UsageStatsManager`（只有应用级数据）。授权后重新拉取 |
| 想知道某个 UI 元素真实坐标 | `adb shell uiautomator dump` 后读 `bounds`，注意截图会缩放（如 1220×2712 的屏幕截图可能是 490×1080） |

## 真机验证约定

- 交互/转场类改动：`adb shell screenrecord` 录屏 + ffmpeg 抽帧逐帧核对，不接受「看起来没问题」；
- 数据类改动：拉数据库（`run-as com.screentrace.app cat databases/screentrace.db`）或对 dump 做归属诊断，
  以实际数值为准；
- 单测要能抓住回归：写完测试后做一次变异（故意改坏实现）确认测试会红。

## 数据口径速查

- `dumpsys usagestats` 不带参数 → 明文（几 MB，含事件流）；带 `--checkin` → CSV（部分机型只有元信息）。
  **两种格式都要能解析**，哪边有数据用哪边。
- 屏幕时长 = 亮屏会话区间**跨拉取并集**（`screen_session` 表）；日聚合从并集重算后与旧值取大。
- 解锁/通知次数以事件表为准（主键去重、只增）。
- 「—」表示数据源缺失，`0` 表示真实的 0 次，两者不可混用。

## 数据与隐私

- 数据全部落本地 Room（`screentrace.db`），无自有服务器；
- `INTERNET` 权限仅用于用户主动开启的云同步与 AI 分析；
- 调试用的 dump / 截图不要提交进仓库（`.smoke/` 已在 `.gitignore` 中）。
