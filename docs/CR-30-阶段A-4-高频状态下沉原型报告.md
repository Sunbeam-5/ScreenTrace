## E1：AppHeader 标题位移进度读取下沉绘制期

**改动**（ScreenScaffold.kt，+6/−9，单变量）：删除组合期 `val titleShiftPx = ...titleShiftDp(it.value)...`
及调试日志；`graphicsLayer { translationX = titleShiftPx }` → `graphicsLayer { val shiftDp =
tabProgress?.let { titleShiftDp(it.value) } ?: 0f; translationX = shiftDp.dp.toPx() }`
（GraphicsLayerScope 实现 Density，绘制期读取）。位移量、横滑行为、Crossfade、
reduceMotion/tabGuard 语义均不变。

## E2：FreshNavBar 跟手模式备用动画条件化

**改动**（FreshNavBar.kt，+30/−22，单变量）：`animatedExpand/animatedContainer/animatedContent`
三个 `animate*AsState` 仅在 `progress == null`（Preview/备用模式）创建；跟手模式
（`progress != null`）直接用 proximity 派生 expand/container/content——三者输出本就
不参与跟手模式展示（原代码 `if (progress != null) proximity else animatedExpand` 等）。
**宽度公式、颜色算法、布局依赖、动画时长、点击区/无障碍/文字/选中态均不变**；
progress.value 组合期读取保留（宽度属布局依赖，本原型不动——GPT E2 边界）。

**操纵检验**（探针构建 far 切换 ×2）：FreshNavBar 执行计数与基线同量级（40/2 切换），

## 3. 与 A-3 模型的印证

- E1/E2 均只压「每帧成本」（中段帧 −4%~−16%），**长尾四格持平**——再次印证 A-3：
  长尾主体在路由写入 burst（AppNav 整树 + 页面树重执行），逐帧消费者只是动画期的持续税。
- V5（A-3 组合诊断）显示长尾可削 60%——但那是多变量+空内容叠加；E1/E2 单变量结果
  符合「长尾需 burst 侧变量（页面稳定化/传播裁剪）才能动」的预判，后续变量待批。
