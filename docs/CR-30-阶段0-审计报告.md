## 6. 周期总结提醒设计 **[v2 重写：调度 + 数据结构冻结]**

### 6.1 功能口径
- 每周总结提醒：**每周一 20:00** 提醒**上一完整自然周**；每月总结提醒：**每月 1 日 20:00** 提醒**上一完整自然月**。
- 双**独立开关**、均**默认关闭**；提醒时间可配置、**默认 20:00**（周月共用一个时间点）。
- 无有效统计数据不发「总结已生成」；点击通知深链「日历 → 周期总结」对应周期；权限诚实（拒绝≠已开启）。

### 6.2 调度设计（**一次性 WorkManager + 本地自然日历计算**，不申请精确闹钟）
- **排期模型**：每个提醒一条**一次性** `OneTimeWorkRequest`（唯一工作名 `weekly_summary_reminder` / `monthly_summary_reminder`，`ExistingWorkPolicy.REPLACE`）。触发时刻＝按**本地自然日历**算出的下一个周期点（周一 20:00 / 月首 20:00），`setInitialDelay` 到该时刻。
- **执行时**：校验「开关仍开 + 周期确已结束 + 该周期未发过（`lastNotifiedWeek/Month` 周期键去重）」→ 发通知 → 写去重键 → **排下一次**（同样一次性 + 自然日历计算）。
- **重新排期触发点**：① 开关开启；② 修改提醒时间（REPLACE 重排）；③ 应用更新/进程重启（Application 启动校对：开关开着且无排期则补排）；④ 设备重启（WorkManager 持久化自动恢复，启动校对兜底）；⑤ **时区/系统时间变化**：每次排期与执行都按**当下本地日历**计算下一触发点，偏移自动吸收（无需监听时区广播；启动校对 + 触发后重排覆盖漂移）。
- **去重**：唯一工作名（防重复排期）+ `lastNotifiedWeek`（ISO 周）/ `lastNotifiedMonth`（YYYY-MM）周期键（防重复发送）；关闭开关 → `cancelUniqueWork`（并清去重键可留）。
- **边界**：非精确执行（接受系统延迟，不承诺整点准点）；不申请 `SCHEDULE_EXACT_ALARM`；无前台服务；电量优化下由 WorkManager 调度约束自管。

### 6.3 数据结构（**冻结，无待定项**）
```
DataStore（SettingsStore，纯本地偏好，零数据库改动）：
  weeklyReminderEnabled:  Boolean = false
  monthlyReminderEnabled: Boolean = false
  reminderTime:           String  = "20:00"   // HH:mm，周/月共用
  lastNotifiedWeek:       String? = null      // ISO 周标识（如 2026-W46），去重键
  lastNotifiedMonth:      String? = null      // YYYY-MM，去重键

备份（BackupSettings，勾选「同时恢复设置」才应用）：
  weeklyReminderEnabled / monthlyReminderEnabled / reminderTime 三项可选导入导出
  alertEnabled（CR-04 旧字段）：**兼容读取后忽略**（不映射到任何新开关），
    导出固定 null

数据库 / CR-28 来源账本 / 统计表：零改动（冻结边界）
```

## 7. 主题颜色来源优先级与互斥 **[v2 定稿]**

**渲染优先级（唯一判定，界面与渲染同源）**：
```
全局色板 =
  dynamicColor 开启 且 API 31+        → 系统动态取色（Material3 colorScheme 与
                                        LocalFreshPalette **同步映射**，图表色一并处理）
  否则 壁纸启用 且 范围＝整套主题      → 壁纸派生整套色板（图表色过对比度保护）
  否则                                → 用户主题（九套预设 / 自定义种子色）
卡片底色（范围＝仅卡片时）              = 壁纸派生卡片色（不影响全局色板）
```

**互斥与界面一致性**（所见即渲染）：
- 范围＝整套主题：「界面风格」九套 + 自定义**置灰**，明示「当前由壁纸驱动」，提供醒目的「切换为跟随主题」（＝切回仅卡片）入口；
- `dynamicColor` 开启：界面明示「由系统动态取色驱动」，九套/自定义/壁纸派生入口同规则置灰；
- 切换任一来源 → 色板层短过渡（**不重建内容分支**，规避整页 Crossfade 闪帧教训）；
- 图表色（`chart1~5`/`heat0~4`）纳入同一优先级链与对比度保护（文字 4.5:1、图形 3:1、相邻色阶亮度差），必要时给图表独立不透明绘图底板。

## 10. 阶段 A 导航状态归属表 **[新]**

| 状态 | 持有者（唯一真相源） | 同步与恢复方式 |
|---|---|---|
| 当前 Tab | `pagerState.currentPage`（**Pager 唯一真相源**，CR-17/22 红线不动） | 点击 tab → `animateScrollToPage` → `snapshotFlow` 单向回写路由；手势滑动 → Pager 直接驱动；**程序化滚动期 `TabScrollGuard` 忽略中间页回写**，落地按实际停留页对齐 |
| Pager 滚动进度 | `pagerState.currentPageOffsetFraction` | TabMotion 连续进度视觉消费（景深/标题位移），不回写状态 |
| 二级/三级页面栈 | 导航栈（页面枚举列表，Overlay 同步消费） | 进入＝压栈**并立即提交状态**（动画只是视觉）；返回＝弹栈同理；**导航状态不依赖动画结束回调** |
| 容器变换视觉 | `ContainerTransformState`（起点登记） | 仅视觉层；中断时按当前进度收尾，状态已定 |
| 页面内容状态 | `AppViewModel`（单例，四页/二级页数据） | 跨导航持久，页面重建不丢 |
| 滚动位置 | 各页 `rememberSaveable` LazyListState（**按页面 key** 存取） | 返回恢复；三级→二级→主逐级恢复 |
| 日期筛选 | `AppViewModel.todaySelection / statsSelection`（CR-15 B 双状态） | 不受导航影响；二级页按 `returnTo` 归属写回（CR-16） |
| 弹层/浮层 | 各自 `mutableStateOf`（DateSheet/设备面板/NoticeBar） | 系统返回先关弹层再退页；导航中断不影响弹层语义 |

**状态同步规则**：点击切换 = 最新意图胜出（新点击取代旧转场，旧协程不抢对齐）；手势切换 = Pager 直接回写（不走守卫）；动画中断 = 按当前进度完成或回退，**状态早已提交**（动画回调不承载业务状态）；快速连续导航 = 队列只保留最新目标，转场可打断、页面不错位、标题跟随实际页。

## 11. 阶段 A 性能基线与验收方案 **[新：先定位、后修复，不预设根因]**

**原则**：不预设「Pager 常驻＝根因」；预加载重设计只是候选方案之一。先测基线定位主因，再对症。

**测量维度与工具**：
| 维度 | 手段 |
|---|---|
| 重组 | Compose RecompositionLogger/组合计数打点（debug 构建埋点，量化每 Tab 切换的重组次数与对象） |
| 绘制 | `dumpsys gfxinfo`（现有脚本基础）+ FrameMetrics（App 内采样帧耗时/掉帧）+ Perfetto trace（GPU/主线程分段） |
| 图表计算 | `MetricBarChart`/`TrendChartMath` 计算打点（进出场与数据绑定耗时） |
| 壁纸解码/模糊 | `WallpaperStore`/`WallpaperBlur` 解码与缓存打点（一次性 vs 每帧） |
| 数据查询 | Room 查询耗时日志（四页 loadAll 各查询分段） |

**场景矩阵**（每项 × vivo/Redmi × 60/120Hz）：点相邻 Tab、点跨两页 Tab、连续快速点三 Tab、横滑、壁纸开/关、深/浅色。记录：帧耗时分布、掉帧率、动画完成时间、重组计数、各维度耗时占比。

**流程**：① 无改动基线 → ② 主因定位（重组/绘制/计算/解码/查询占比排序）→ ③ 对症方案（预加载守卫 / 保活策略 / 图表缓存 / 壁纸缓存策略等）→ ④ 同矩阵复测对比 → ⑤ 录屏逐帧复核（白帧/拖影/瞬移）。**验收**：目标场景掉帧率与帧耗时显著改善、无回归、无空帧。

## 12. Motion System 约束 **[新]**

1. **统一参数入口**：`MotionTokens`（时长/曲线/距离/透明度/减少动画开关）唯一出处；组件不得自设动画参数（场景档位见任务书基准，真机调校后冻结数值）。
2. **进出独立曲线**：返回不得使用进入曲线的反向；返回＝立即反馈、内容先淡出、锚点收尾、干脆落位。
3. **动画可中断**：任何转场可被打断并正确衔接（状态已先于动画提交）；快速连续导航最新意图胜出。
4. **减少动画统一降级**：全局一处判定（位移/缩放 → 短淡入），各场景降级规则统一。
5. **导航状态不得依赖动画结束回调更新**（红线）；整页 `Crossfade`/`AnimatedContent` 不得用于导航状态过渡（CR-15/23 教训固化）。
